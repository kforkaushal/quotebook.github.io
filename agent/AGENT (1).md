# Quotebook Agent Documentation

This document serves as the definitive technical guide for the **Quotebook** project, outlining its architecture, data flow, build processes, and critical implementation details. It is designed to help AI agents, developers, and contributors understand the system without needing to read every line of code.

## 1. Project Overview

**Quotebook** is a static, vanilla-JS web application that functions as an editorial quote library and a visual poster studio. The application hosts over 39,000 curated quotes across 57 categories and integrates with the **Pixabay API** for live photography.

The core philosophy of the project is to remain **framework-free** (HTML, CSS, ES6+ JavaScript) while utilizing programmatic SEO techniques via build-time scripts to generate thousands of static HTML pages for long-tail search queries.

## 2. Architectural Structure

The application is composed of three main layers: the frontend UI, the data pipeline, and the build-time SEO generators.

### 2.1 Frontend Application
The frontend relies on three primary HTML entry points and two core JavaScript engines:

*   **`index.html`**: The marketing landing page featuring the hero device mockup, dynamic marquee, and feature showcases.
*   **`quotes.html`**: The primary interactive application. It loads the data, handles filtering, and manages the Poster Studio and Zen Mode modals.
*   **`poster.html`**: A dedicated standalone interface for the Canvas Poster Studio.
*   **`src/js/app.js`**: The main application controller. It handles state management, data fetching, DOM manipulation, event listening, and progressive enhancement for statically generated pages.
*   **`src/js/poster.js`**: An isolated class (`PosterStudio`) responsible for all HTML5 Canvas rendering logic, image loading, and PNG generation.
*   **`src/css/style.css`**: The comprehensive design system, utilizing CSS variables for theming, glassmorphism, and responsive layouts.

### 2.2 Data Pipeline
The application uses a tiered data loading strategy to optimize performance:

1.  **`data/featured_quotes.json`**: A lightweight dataset loaded immediately on page load to provide instant UI feedback (sub-10ms render).
2.  **`data/quotes_8000_plus.json`**: The massive 39,000+ quote database loaded in the background shortly after the initial render.
3.  **`data/quotes_enriched.json`**: A fully augmented dataset generated by a build script, containing semantic metadata (tags, occasion, relationship, tone) used exclusively for the programmatic SEO pages.

### 2.3 API Integrations
*   **Pixabay API**: Fetched client-side via `fetchPixabayImages()` in `app.js`. It caches results in memory (`state.pixabayCache`) to prevent redundant API calls and respects a "Lite Mode" toggle to save bandwidth.
*   **Wikipedia REST API**: Used to dynamically fetch author profiles (images, biographies) and generate the Instagram-style Author Stories feature.

## 3. Build Process & Programmatic SEO

Because the core dataset is too large to render into static files directly, Quotebook employs a dual-generation strategy using Node.js and PowerShell scripts.

### 3.1 Enrichment Script (`tag-database-rules.js`)
Before generating SEO pages, the raw database must be enriched. This script analyzes every quote using regex heuristics to classify them by:
*   **Format** (Quote, Wish, Caption, Shayari)
*   **Occasion** (Birthday, Anniversary, Good Morning, etc.)
*   **Relationship** (Boyfriend, Boss, Colleague, etc.)
*   **Tone** (Funny, Romantic, Savage/Attitude)

### 3.2 Standard Generators (`generate-static-pages.js`)
This script reads the standard JSON and generates static HTML files for:
*   Top 57 Categories (e.g., `/quotes/wisdom.html`)
*   Top 100 Authors (e.g., `/authors/mark-twain.html`)
It limits each page to the top 30 most popular quotes to keep file sizes manageable and SEO-friendly.

### 3.3 Programmatic SEO Network (`generate-seo-network.ps1`)
This is the most complex build step. It reads the *enriched* database and a predefined "Search-Intent Registry" (e.g., "Birthday Wishes for Best Friend"). It applies complex boolean filtering to find relevant quotes and generates highly specific long-tail pages (e.g., `birthday-wishes-for-best-friend.html`). These pages include custom intro text, sibling recommendations, and interactive card bindings.

## 4. Critical Implementation Details & State

### 4.1 Global State (`app.js`)
The application maintains a global `state` object that tracks:
*   `allQuotes` vs `filteredQuotes` arrays.
*   Active filters (`activeCategory`, `searchQuery`, `selectedAuthor`, `sortBy`).
*   `dataSaver` boolean (enabled via `localStorage`).
*   Zen Mode and Poster Studio instances.

### 4.2 DOM Dependencies
The application relies heavily on specific DOM IDs. When modifying `quotes.html` or the generators, ensure the following IDs are preserved:
*   **Grids & Lists**: `quotesGrid`, `bookmarksList`, `todaysQuotesGrid`.
*   **Modals**: `posterModal`, `zenModal`, `storyViewerModal`, `bookmarksDrawerBackdrop`.
*   **Poster Studio**: `posterCanvas`, `pixabayThumbs`, `overlayPresets`, `fontPresets`, `ratioSelector`.
*   **Hero**: `heroBackdrop`, `heroQuoteText`, `heroAuthorTag`.

### 4.3 Poster Studio Logic
The `PosterStudio` class in `poster.js` manages a 1080x1080 (or similar) canvas. It draws layers sequentially:
1.  Background image (or fallback gradient).
2.  Overlay tint (e.g., `light-glass`, `warm-sun`).
3.  Decorative inner frame and watermarks.
4.  Typography (auto-scaling font size based on quote length).
5.  Text wrapping is handled manually via the `wrapText()` method.

## 5. SEO Infrastructure
The generated static pages include full SEO scaffolding:
*   Unique `<title>` and `<meta name="description">`.
*   Open Graph and Twitter Card tags.
*   JSON-LD Schema (Breadcrumbs, WebPage, or SearchAction depending on the page type).
*   A dynamically rewritten `sitemap.xml` that aggregates all generated URLs.

## 6. UX & Accessibility
*   **Lite Mode**: Disables Pixabay image fetching and clears existing background images to reduce data usage.
*   **Reduced Motion**: The application supports `prefers-reduced-motion` via CSS variables to disable ambient animations for users who require it.
*   **Scroll Reveal**: An `IntersectionObserver` in `app.js` handles staggered fade-ins for quote cards to ensure performance-friendly animations.
